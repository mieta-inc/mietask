# タスクチェック

4つのサービスを見て「**自分が動かないと止まるもの**」だけを拾い、返信案まで用意する。

**このスキルは設定不要です。** 実行するアカウントを自動で判別するので、誰が使っても動きます。

---

## 前提

以下のコネクタが接続されている必要があります。未接続のものはスキップし、**出力に必ず明記します**（黙って省略しない）。

| | 何を見るか |
|---|---|
| Slack | 自分宛メンション・DM・自分が参加したスレッドの新着 |
| Gmail | 自分宛のメール（未読は使わない。後述） |
| Googleカレンダー | 今日〜2週間の予定、出欠未回答、準備が必要な会議 |
| Googleドライブ | 自分宛のコメント、共有された最近のファイル |

MCPツール名にはUUIDが含まれ環境ごとに違うので、**名前をハードコードせずToolSearchのキーワード検索で解決**してください。

```
ToolSearch("slack search read thread")
ToolSearch("gmail search threads get thread")
ToolSearch("calendar list events")
ToolSearch("drive search files recent")
```

---

## STEP 0: 自分が誰かを特定する

設定ファイルが無くても動くよう、実行時に判別します。

- **Slack**: 検索ツールの説明文に `Current logged in user's user_id is U0XXXXXXX` と書かれています。ここから取得
- **Gmail**: 検索クエリで `to:me` が使えます
- **カレンダー**: `primary` が自分のカレンダー
- **Drive**: クエリで `owner = 'me'` / `sharedWithMe = true` が使えます

### 設定ファイルがあれば読む（任意）

`~/.mietask/config.json`（絶対パスは `bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" paths home` で分かる）があれば読み、**除外ルールを必ず通します。**
無ければ上の自動判別だけで進めます。どちらでも動きます。

| 見るところ | 効き方 |
|---|---|
| `gmail.exclude_senders` / `exclude_sender_patterns` | 通知・メルマガを落とす |
| `gmail.exclude_subject_prefixes` | カレンダーの招待・承諾通知を落とす |
| `gmail.vip_senders` | この送信元は必ずP1 |
| `slack.exclude_channels` | 見ないチャンネル |
| `priority_rules` | 優先度の付け方 |
| `dismissed_refs` | 「対応不要」と言われたもの。**二度と出さない** |

**この除外リストが育つほど精度が上がります。** 使い始めは外れが出るので、
ノイズを見つけたら `exclude_senders` に足すよう本人に促してください。

## STEP 1: 4サービスを並列で巡回する

**必ず同一メッセージ内で並列に呼びます。** 順番に実行すると待ち時間が積み上がります。

### Slack

```
検索: <@自分のuser_id> after:<7日前>
```

さらに DM と、自分が発言したスレッドの新着を確認します。
`ref` は `slack:<channel_id>:<thread_ts>` の形で覚えておき、permalink を必ず保持します。

### Gmail

```
to:me newer_than:7d -category:promotions -category:social -category:forums -in:sent
```

**⚠️ 未読・受信トレイ在中を「要対応」の目印にしないでください。** メールが溜まっている人ほど誤爆します。
代わりに次で絞ります。

- 送信者が `no-reply@` `noreply@` `newsletter@` `marketing@` を含む → 捨てる
- 件名が `招待:` `承諾:` `辞退:` `更新:` `キャンセル:` で始まる → 捨てる（カレンダー側で拾うため）
- 自分が `to` に入っていない（cc のみ・共有アドレス宛）→ **本文に自分の名前で依頼・質問がある場合だけ拾う**

例外として、次は `no-reply` でも**拾います**:

| 送信元 | なぜ |
|---|---|
| `comments-noreply@docs.google.com` | ドキュメントのコメント。返信が要ることが多い |
| `gemini-notes@google.com` | Meetの議事メモ。**後述のSTEP 2.5で必ず処理** |

### Googleカレンダー

`primary` の今日〜14日先を取得します。

- **出欠が未回答（needsAction）の予定** → タスクにする
- 定例・訪問・商談・発表など準備が要りそうな予定で、準備の跡が見当たらないもの → 確認を促す
- 対面の予定は前後の移動時間も見る

### Googleドライブ

- 自分に共有された最近更新のファイル
- 自分宛のコメント（Gmail経由の `comments-noreply` と突き合わせる）

## STEP 2: タスクにするか判定する

判定軸はひとつだけ。**「自分が何かをしないと前に進まないか？」**

**拾う**
- 自分への依頼・質問・確認依頼
- 自分が返信しないと相手が止まるもの
- 期限のある提出物・承認・出欠回答
- 準備が必要な会議

**拾わない**
- 情報共有・FYI・雑談・リアクションのみ
- 自分以外が明らかに対応するもの
- 自動通知（承認完了・ログイン通知など、行動が要らないもの）

**迷ったら拾う。** 見落とすより、ユーザーに「これは不要」と一言消してもらうほうが安全です。

---

## STEP 2.5: 会議の議事録からアクションを拾う

**ここが一番の穴場です。** 会議で引き受けた宿題はどこにも記録されず消えがちです。

Gmailで `from:gemini-notes@google.com` を検索します。本文の「**推奨される次のステップ**」に
`[担当者名] 見出し: 内容` の形でアクションが並んでいます。

- **自分の名前が付いているものだけ**をタスクにする
- 他人のアクションは、**それが終わらないと自分が動けない場合だけ**「相手待ち」として記録
- 会議中に決まった期限が本文にあれば使う。なければ期限なし。**議事録にない期限を推測で作らない**
- タスクに `📝 議事録から` と付けて、出所が分かるようにする

**注意**: Geminiの文字起こしには誤りがあります（人名が崩れるなど）。また「次のステップ」はGeminiの推測なので、
実際の合意と違うことがあります。**不明瞭な箇所は推測で補わず「要確認」と書いてください。**

**取れない会議があることも伝えてください。** Geminiメモは Google Meet でメモ機能をONにした会議のみです。
Teams会議・対面の打合せは取得できません。該当しそうな予定が直前にあった場合は
`※ 8/12の訪問(対面)は議事録が取れないため、そこで決まった分は含みません` と明記します。

---

## STEP 3: 返信案をつくる

**返信が必要なタスクには、そのままコピペできる下書きを添えます。**

### 返信案の原則

1. **結論から書く。** 「確認します」で終わる返信は書かない。Yes / No / 条件付き のどれかを明示する
2. **期限を返す。** 「対応します」ではなく「◯日までに対応します」
3. **相手のトーンに合わせる。** Slackの砕けたスレッドに硬い敬語を返さない。元のスレッドの文体を見る
4. **判断できない部分は空欄にして [ここを埋める] と書く。** 勝手に約束しない
5. **短く。** Slackは3行以内、メールは定型の挨拶＋本文5行以内を目安に

### 判断材料が足りないとき

日程・可否・金額など**本人しか決められないこと**は、選択肢の形で出します。

```
返信案（どちらか選んでください）
 A案: 「8/20までに対応します」
 B案: 「今週は手が回らないので、来週前半でもよいですか？」
```

### 出力の形

コピペしやすいようにコードブロックに入れます。**絶対に送信しません。**

## 出力書式

```
🗓 2026年8月14日(木) 09:00 時点
巡回: Slack ✓ / Gmail ✓ / カレンダー ✓ / Drive ✓

━━ ⚠️ 期限超過 (1) ━━
 1. 見積書の提出   期限 8/12(火) ← 2日超過 / 山田さん(Slack #sales) [→](permalink)
    → 次の一手: 見積書ドラフトを確認して返信

    返信案:
    ```
    お待たせしてすみません。見積書は本日中にお送りします。
    ```

━━ 🔴 今日中 (2) ━━
 2. 💬 田中さんへの返信: 8/20訪問の参加可否   [→](permalink)
    → 次の一手: 参加できるか回答する

    返信案（どちらか選んでください）:
    ```
    A: 8/20の訪問、参加します。10時に現地でお願いします。
    B: 8/20は別件が入っており難しいです。翌週でも大丈夫でしょうか？
    ```

 3. 📝 提案書のドラフト作成   議事録から（8/13 定例）
    → 次の一手: 開発パートを執筆する

━━ 🟡 今週中 (4) ━━
 …

━━ ⏳ 相手待ち (1) ━━
 8. 佐藤さんのデータ提供待ち / 3営業日 動きなし
    → 催促しますか？（催促文の案も出せます）

━━ 📅 予定の確認事項 ━━
 • 8/15 10:00「定例MTG」の出欠が未回答です（開始まで25時間）
 • 8/16「訪問：A社」の準備タスクが見当たりません

──────────
合計 9件（要返信 3件）
※ 8/12の訪問(対面)は議事録が取れないため、そこで決まった分は含みません
```

### 書式のルール

- **期限超過は必ず最上位。** 何日超過しているかを書く
- 該当0件の区分は**見出しごと省略**する
- 各区分は最大5件。超えたら `…他N件` と**明示する**（黙って切らない）
- 推測した期限には必ず `(推定)` を付ける
- 返信が必要なものには `💬`、議事録由来には `📝` を付ける
- Slack/Gmailのリンクを必ず付ける
- 1件もなければ `✨ 対応が必要なものはありません`

---

## 絶対にやらないこと

**メール送信・Slack投稿・カレンダーの予定作成/変更/削除・ファイルの編集は行いません。**

このスキルは**読み取りと提案だけ**です。返信案を作っても送信はしません。
送るのは本人です。「送っておきますか？」とも聞きません。

---

## 引数

- `task-check` — 直近7日を巡回
- `task-check 今日` — 今日が期限のものだけ
- `task-check 返信だけ` — 返信が必要なものだけ、返信案つきで
- `task-check 3日` — 期間を指定

---

## 続けて使うなら（任意）

このスキルは状態を持たないので、毎回ゼロから巡回します。
「一度見たものを二度出さない」「完了したものを覚えておく」ようにしたい場合は、
実行したディレクトリに `tasks.json` を作って以下を持たせてください。

```jsonc
{
  "tasks": [{
    "id": "t001",
    "title": "…",
    "source": { "app": "slack", "ref": "slack:C123:1712...", "url": "…" },
    "due": "2026-08-20",
    "status": "open | done | waiting | dropped",
    "next_action": "…"
  }],
  "dismissed_refs": ["…"]   // 「対応不要」と判断したもの。二度と出さない
}
```

**`source.ref` が一致するタスクは新規作成せず更新するだけ**にします。これが重複を防ぐ唯一の仕組みです。
巡回で `status` を書き換えないでください（本人が完了にしたものを open に戻さないため）。
