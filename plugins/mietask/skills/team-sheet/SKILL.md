# 1on1シート

メンバー1人ぶんの状況を1枚にまとめる。材料は2つで、**混ぜずに並べる。**

| | 出どころ | 何がわかるか |
|---|---|---|
| 個人のタスク | チームのまとめチャンネル（各メンバーのミエタスクが毎朝投稿） | 期限超過・今日・今週・相手待ち、完了、ステイ、本人のメモ |
| 担当案件 | Notion の MTD（プロジェクトDB・タスクDB） | どの案件で何の役割か、案件ごとの未完了・超過・次の期日 |

**このスキルは読むだけ。** Notionのタスクやステータスを直さない。Slackに投稿しない。
結果はこの会話の中に出す。

---

## 0. チームの設定を読む

`~/.mietask/team.json`（`MIETASK_HOME` で変更可）を読む。

```json
{
  "team": "PD",
  "channel": "C0XXXXXXXXX",
  "notion": {
    "projects": "collection://...",
    "tasks": "collection://..."
  },
  "members": [
    {"name": "三上 詩乃", "slack_id": "U0...", "notion_user": "user://..."}
  ]
}
```

- 無ければ、チーム名・まとめチャンネル・メンバーの名前を本人に聞いて作る
- `notion` の2つは管理者から受け取る（社内の値なので、このリポジトリには書かない）
- `slack_id` は Slack のユーザー検索で名前から引く
- `notion_user` は Slack のプロフィールのメールで Notion のユーザーを探して埋める。
  **メールで一致しないときは推測で選ばない。** 「Notionで見つかりません」と書いて、その人のMTD欄は空にする
- 一度埋めた値はファイルに書き戻す。毎回引き直さない

## 1. 個人のタスク（まとめチャンネル）

まとめチャンネルの直近8日を読み、親が `:bust_in_silhouette: *<名前>*` で始まる投稿を拾う。
最新の投稿はスレッドも読む。

| 拾うもの | どこから |
|---|---|
| 今の件数（超過・今日・今週・相手待ち） | 最新の親の1行目 |
| 件数の推移 | 各日の親の1行目。**増えているか減っているか**だけを見る |
| 完了した件数 | 親の「昨日の完了N件」 |
| ステイが続いているもの | スレッドの `↻ ステイN回`。3回以上を挙げる |
| 期限超過の中身 | 最新のスレッドの期限超過。何日超過かも |
| 本人のメモ | `📝 …のメモ:`。**言い換えずにそのまま出す** |

投稿が1件も無ければ「ミエタスク未導入（または直近8日の投稿なし）」と書いて、MTD欄だけ出す。

## 2. 担当案件（MTD）

データソースは `team.json` の `notion.projects`（プロジェクトDB）と `notion.tasks`（タスクDB）。
以下のSQLでは `<tasks>` `<projects>` と書く。

**① 担当している案件と役割**（rows モード）

プロジェクトDBで、`プロジェクトリード` / `PM担当` / `CC担当` / `SP担当` のどれかにその人が入り、
`ステータス` が `完了` でも `中止` でもないもの。案件名はタイトル（キーは空文字 `""`）。
役割は入っている欄の名前（リード・PM・CC・SP）。

**② 案件ごとのタスクの進み**（sql モード、2つのデータソースを結合）

```sql
SELECT p.url AS project_url, p."ステータス" AS pstatus,
  COUNT(*) AS open_n,
  SUM(CASE WHEN t."date:期日:start" <  date('now','localtime')
            AND t."date:期日:start" >= date('now','localtime','-30 day') THEN 1 ELSE 0 END) AS overdue_n,
  SUM(CASE WHEN t."date:期日:start" <  date('now','localtime','-30 day') THEN 1 ELSE 0 END) AS stale_n,
  MIN(CASE WHEN t."date:期日:start" >= date('now','localtime') THEN t."date:期日:start" END) AS next_due
FROM "<tasks>" t
LEFT JOIN json_each(CASE WHEN t."プログラム" IS NULL OR t."プログラム" = '' THEN '[null]' ELSE t."プログラム" END) j
LEFT JOIN "<projects>" p ON p.url = j.value
WHERE t."担当者" LIKE ?1 AND t."ステータス" <> '完了'
GROUP BY p.url
```

`?1` には `%<notion_user の UUID 部分>%` を渡す。

- プロジェクトDBのタイトル列はSQLで読めない。案件名は①の結果とページIDで突き合わせる
  （SQLのURLは `/p/` が無い形なので、末尾の32桁で比べる）
- ①に無い案件（本人が担当欄に入っていないが、タスクだけ持っている案件）は、
  タスクDBの `タスク` 関連で案件を引く（rows モード、`relation_contains`）
- `project_url` が null の行は「案件外のタスク」

**期限から30日以上たった未完了は「長く止まっている」に分ける。** MTDには期限を過ぎたまま
閉じられていないタスクが残っていることが多く、「超過」に混ぜると今週の遅れが見えなくなる。

## 3. 1枚にまとめる

```
👤 三上 詩乃さん（11/11〜11/17）

■ 個人のタスク（ミエタスク）
  ⚠超過1 / 🔴今日2 / 🟡今週5 / ⏳相手待ち2   先週より超過 +1
  今週の完了 6件
  ステイが続いているもの: 〇〇の資料（↻4回）
  期限超過: 〇〇への返信（3日超過）
    📝 11/14のメモ: 先方の回答待ち

■ 担当案件（MTD）
  大阪国際（CC）    未完了3  超過1   次の期日 11/18
  淳心（CC）        未完了1          次の期日 11/25
  案件外のタスク    未完了2

■ 長く止まっているもの（期限から30日以上）
  MTD 3件（〇〇 9/30、〇〇 10/2 …）→ 閉じてよいか確認

■ 気づいたこと
  • 中止になった案件にタスクが1件残っている
  • 「〇〇」はミエタスクとMTDの両方にある
```

### 書き方のルール

- **人を比べない。** 「〇〇さんより多い」とは書かない。除外ルールやタスクの切り方が人ごとに違うので、
  件数の比較に意味はない。見るのは**同じ人の変化**だけ
- 本人のメモは言い換えない・要約しない
- 推測で埋めない。読み取れないものは「要確認」と書く
- 「気づいたこと」は、中止・完了済みの案件に残るタスク、期間が終わった案件、
  ミエタスクとMTDの重複（タイトルがほぼ同じもの）、ステイ3回以上。**無ければ節ごと省く**
- 各節は最大5行。超えたら「…他N件」と**明示する**

## 4. チーム全体（「PDの状況」と言われたとき）

メンバー全員を1行ずつ。詳しく見たい人を選んでもらう。

```
PD（11/17時点）
  三上   ⚠1 🔴2 🟡5 ⏳2   MTD 未完了6（超過1・止まり3）
  貝塚   🔴1 🟡4          MTD 未完了2
  小川   ミエタスク未導入  MTD 未完了9（超過2）
```

並べる順はメンバー表の順。**件数で並べ替えない**（順位に見えるため）。

## やらないこと

- Notion・Slackへの書き込み（タスクの完了・ステータス変更・投稿）
- 人の比較・順位付け
- 返信案や本人の下書きを出す（まとめチャンネルにも入っていない）
- メールで一致しない人を名前の似た別人で埋める
