# 1on1シート

管理者が知りたいのは次の4つ。**タスクを消化しているかどうかは主眼ではない。**

1. その人が**どの案件を抱えているか**
2. それぞれが**どういう状態か**（制作物がどこまで進んでいるか）
3. **抱えすぎていないか**（並行している数と、終了・開始の予定日）
4. **詰まっているところはないか**

これを並べて、**新規案件に誰を当てるか**を判断できるようにする。

| | 出どころ | わかること |
|---|---|---|
| 案件 | Notion の MTD（プロジェクトDB） | 担当している案件・役割・種別・期間 |
| 制作物の進み | Notion の MTD（タスクDB） | 案件ごとに今動いているもの（進行中・確認待ちのタスク） |
| MTDの外の仕事 | 各自のミエタスクが毎朝送る、案件ごとの要約 | 社内の案件・リードしている取り組みなど。案件名・状態・次の期限だけ |

**読むだけ。** Notionのタスクや案件のステータスを直さない。Slackに投稿しない。結果はこの会話に出す。

## 0. チームとメンバーを読む

以下 `$B` = `${CLAUDE_PLUGIN_ROOT}/bin/mietask` とする。

**管理台帳（スプレッドシート）から読む。** 「PMの状況」なら `--team pm`。親チームを指すと、
その下のチーム（PM1・PM2…）もまとめて返る。

```bash
bash "$B" registry --team pm
```

| 返ってくるもの | 使い方 |
|---|---|
| `teams` | 対象のチーム。`channel` がそのチームのまとめチャンネル（下のチームの分も読む） |
| `members` | 対象のメンバー。名前・Slack ID・メール・所属・状態。**状態が「停止」の人は出さない** |
| `settings` | `notion_projects`・`notion_tasks` が MTD の場所（collection://…） |
| `activity` | 各自のミエタスクが最後に動いた日時。ここに無い人は「ミエタスク未導入」 |
| `shared` | 各自のミエタスクが毎朝送る、案件ごとの要約（直近8日のうち最新）。`items` に 案件名・状態・次の期限（下の 3） |
| `daily`・`system_admin` | システム管理者のときだけ返る、動作の点検用の件数。**状況のまとめには使わない**（下の 3） |

- 並び順は台帳のメンバーの順
- 「管理台帳を使っていません」と出たら、従来どおり `$H/team.json` を読む（`$H` は `bash "$B" paths home` の出力。
  形は `{"team","channel","notion":{"projects","tasks"},"members":[{"name","slack_id","notion_user"}]}`）
- Notion のユーザーIDは、台帳の `members[].notion_user` を使う。空の人だけ、Notion の検索で `query_type: "user"` にしてメールを渡して引く。
  ユーザー一覧（get-users）には全員が出ないので使わない。引けた値は `$H/notion-users.json`（メール → `user://…`）に
  控えて次回から使う。**メールで一致しないときは推測で選ばない。** Slack と Notion でメールが違う人がいるので、管理者に聞く

以下、`<projects>` `<tasks>` は MTD の場所、`<uid>` は Notion ユーザーIDの UUID 部分。

## 1. 案件を時期で分ける

**案件のステータスではなく、期間で判断する。** MTDには期間が終わっても「進行中」のままの案件が
多く、ステータスで数えると抱えている数が実態より多く出る。

| 区分 | 条件（開始 = 期間の開始、無ければ授業初日） |
|---|---|
| 今走っている | 開始 ≦ 今日 かつ（終了 ≧ 今日、または終了が空で授業初日が120日以内） |
| もうすぐ始まる | 今日 < 開始 ≦ 60日後 |
| もうすぐ終わる | 今日 ≦ 終了 ≦ 30日後 |
| 2か月先も続く | 終了 > 60日後 |
| 期間が過ぎて未完了 | 終了 < 今日 で、ステータスが完了・中止でない（**案件側の整理**として末尾に出すだけ） |

担当の判定は `PM担当` / `CC担当` / `SP担当`。`プロジェクトリード` と `連携メンバー` は
役割欄に書くが、負荷の数には入れない（社内案件・手伝いが多いため）。

**チーム全体**（1回で全員分）:

```sql
WITH ids(ord, name, uid) AS (SELECT 1,'三上','…' UNION ALL …),
x AS (
  SELECT i.ord, i.name, p."プログラム種別" AS kind, p."ステータス" AS st,
    COALESCE(p."date:期間:start", p."date:授業初日:start") AS s,
    p."date:期間:end" AS e, p."date:授業初日:start" AS fd
  FROM ids i JOIN "<projects>" p
    ON p."CC担当" LIKE '%'||i.uid||'%' OR p."PM担当" LIKE '%'||i.uid||'%' OR p."SP担当" LIKE '%'||i.uid||'%'
)
SELECT ord, name,
  SUM(CASE WHEN st<>'中止' AND s<=date('now','localtime')
           AND (e>=date('now','localtime') OR (e IS NULL AND fd>=date('now','localtime','-120 day'))) THEN 1 ELSE 0 END) AS running,
  SUM(CASE WHEN st<>'中止' AND s>date('now','localtime') AND s<=date('now','localtime','+60 day') THEN 1 ELSE 0 END) AS starting60,
  SUM(CASE WHEN st<>'中止' AND e>=date('now','localtime') AND e<=date('now','localtime','+30 day') THEN 1 ELSE 0 END) AS ending30,
  SUM(CASE WHEN st<>'中止' AND e>date('now','localtime','+60 day') THEN 1 ELSE 0 END) AS beyond60,
  SUM(CASE WHEN st NOT IN ('完了','中止') AND e<date('now','localtime') THEN 1 ELSE 0 END) AS ended_open,
  SUM(CASE WHEN kind='WS' THEN 1 ELSE 0 END) AS ws, SUM(CASE WHEN kind='ゼミ' THEN 1 ELSE 0 END) AS zemi,
  SUM(CASE WHEN kind='FW' THEN 1 ELSE 0 END) AS fw, SUM(CASE WHEN kind='修学旅行' THEN 1 ELSE 0 END) AS trip
FROM x GROUP BY ord, name ORDER BY ord
```

担当案件が1件も無いメンバーは結果から落ちる。表には「MTDに担当案件なし」と出す（0件と区別する）。

**1人ぶんの案件一覧**: 同じ条件で1人に絞り、`substr(p.url,-32)` をページIDとして取る。
案件名はSQLで読めない（タイトル列が空の名前）ので、rows モードで `CC担当` などに
`person_contains`（値は `user://<uid>`）をかけて取り、キー `""` が案件名。
**rows の結果は大きいので、保存されたファイルから必要な列だけを抜く。**

## 2. 制作物の進み（案件ごとに今動いているもの）

```sql
SELECT substr(j.value,-32) AS pid,
  group_concat(CASE WHEN t."ステータス" IN ('進行中','確認待ち','保留')
                    THEN t."タスク名"||'['||t."ステータス"||']' END, ' / ') AS moving,
  group_concat(DISTINCT t."タスクカテゴリ") AS cats
FROM "<tasks>" t,
  json_each(CASE WHEN t."プログラム" IS NULL OR t."プログラム"='' THEN '[null]' ELSE t."プログラム" END) j
WHERE t."担当者" LIKE '%<uid>%' AND t."ステータス" <> '完了'
GROUP BY pid
```

- **「今やっていること」として、進行中・確認待ちのタスク名を案件ごとに並べる。** これで何を作っているところかがわかる
  （例: 「2学期ワークシート最終化・講師コンテンツ3本・中間プレゼン②スライド」）
- 件数や消化率は出さない。管理者が見たいのは「何を作っているところか」
- `pid` が null の行は「案件外の制作」

## 3. MTDの外の仕事（ミエタスクの案件ごとの要約）

MTD はプログラム（授業）の案件のタスク管理で、社内の案件やリードしている取り組みは出てこない。
そこは `registry` の `shared` を使う。各自のミエタスクが毎朝、その日の一覧を案件ごとにまとめて送ったもの。

- 1件は **案件名・状態（動いている／相手待ち／期限が過ぎたものあり）・次の期限** だけ。そのまま書く
- 日付が今日でなければ「ミエタスクは M/D から届いていない」と書く（毎朝の実行が止まっているかもしれない。空いているとは読まない）
- `shared` に入っていない人は、ミエタスク未導入か、まだ一度も届いていない。「ここからは見えない」と書く
- **タスクの題名・メモ・どこから来たかは届かない作り。** 推測で補わない（DM・非公開チャンネル・メールの内容が入るため）
- 件数（超過・今日・今週）はシステム管理者の点検用で、状況のまとめには使わない。
  案件ごとに重さが違うので、件数が多いことと忙しいことは一致しない

## 4. 1人ぶんのシート

```
👤 三上 詩乃さん（11/14時点）

■ 抱えている案件
  今走っている 7（ゼミ2・WS4・FW1）／ もうすぐ終わる 3 ／ もうすぐ始まる 0
  ・26順天高1ゼミ（CC・〜3/31）
      今: 2学期ワークシート最終化、講師コンテンツ3本、中間プレゼン②スライド
  ・26箕面高1 社会体験FW（CC・〜3/13）
      今: 講師打合せ設定、ワークシートたたき、希望調査資料、進行スライド
  ・26広島学院 高1 FW（CC・〜11/17）  今動いているものなし
  …他4件
  案件外の制作: 動画修正依頼3本、都立短期講座コンテンツ ほか

■ 並行と予定
  今は7案件が並行。終了予定 11/17・11/25・12/4、開始予定なし

■ 詰まっていそうなところ
  ・26順天高1ゼミ：講師スライドが確認待ち

■ MTDの外の案件（ミエタスクから・11/14 7:00時点）
  ・社内の動画制作フロー整備 — 動いている（次の期限 11/20）
  ・新規講師の開拓 — 相手待ち

■ 案件側の整理（期間が過ぎて未完了のまま）
  都立富士森（〜7/31）、藤嶺藤沢（〜6/30）、箕面インド修学旅行（〜9/30）
```

- 「今走っている」は終了が近い順。各案件の「今:」は最大4つ、超えたら「ほか」
- **予測しない。** 「空く」「減らない」「振りやすい」「山場」のような見立ては書かない。
  終了予定・開始予定の日付は事実として書いてよいが、そこから先（空くかどうか）は管理者が判断する。
  日付の入っていない仕事や、次の準備・延長があるので、MTDの期間だけでは読めない（2026-11-14 河村さん）
- 「詰まっていそうなところ」は、MTD の確認待ち・保留のタスク。無ければ節ごと省く
- 「案件側の整理」は末尾に1行。責める書き方にしない

## 5. チーム全体（「PDの状況」「PMの状況」など）

**件数の表にしない。** 管理者が見たいのは数ではなく、**誰が何の案件を持っていて、それぞれ今何を作っているか**。

**最初にメンバー全員の一覧を出し、1人1行で状況がわかるようにする。** そのあとに一人ずつの詳細を並べる。
Slackに出す場合は、一覧を親メッセージ、一人ずつの詳細をスレッドにする。

```
:busts_in_silhouette: *PDの状況*　11/14時点

• *小川*　10案件、来週以降に2件始まる予定
• *山下*　4案件、1月から修学旅行　:warning: 講師スライドが確認待ち
• *三上*　7案件、うち3件が12/4までに終了予定
• *河村*　MTDの担当案件なし／ほかに5案件（ミエマス、TiB講義スライド、社内DX ほか）
• *シュバーニ・松村*　MTDに担当なし。ミエタスクの要約も届いておらず、ここからは見えない

一人ずつの詳細はスレッドに。出どころはMTD（Notion）と、各自のミエタスクが送る案件ごとの要約です。
```

一覧の1行は「並行の数＋終了・開始の予定（事実だけ）」。詰まりがあれば `:warning:` を付けて同じ行に書く。見立ては書かない。

MTDに登録されていない仕事（授業に紐づかない社内の仕事、Slackやメールで来た依頼）は、ミエタスクの要約（3）から「ほかにN案件」として同じ行に書く。
MTDにもミエタスクの要約にも何も無い人は「ここからは見えない」と正直に書く（ミエタスクの件数で埋めない）。

詳細は一人ずつ、案件名と「今:」を並べる。最後に「これまでの担当（種別ごとの件数）」を1行。見立ては書かない。

```
■ 三上さん — 7案件、うち3件が12/4までに終了予定
・26順天高1ゼミ（〜3/31）　今: 2学期ワークシート最終化、講師コンテンツ3本、中間プレゼン②スライド
・26箕面高1 社会体験FW（〜3/13）　今: 講師打合せ設定、ワークシートたたき、希望調査資料、進行スライド
・もうすぐ終わる: 広島学院 高1 FW（11/17）、大阪国際WS（11/25）、都立大崎（12/4）
・他に 箕面高2長期ゼミ、巣鴨中3
・案件外: 動画修正3本、都立短期講座のコンテンツ
・これまでの担当（MTD・終了分を含む）：WS 9・ゼミ 2・FW 1・修学旅行 1
```

- 見出しの横に、並行している数と終了・開始の予定日を書く（事実だけ）
- 「今:」が付くのは、動いているタスク（進行中・確認待ち）がある案件だけ。無い案件は「他に」にまとめる
- **CC担当ではない案件で手を動かしているもの**も拾う（例: 担当外の案件でワークシートを作っている）
- 案件外の制作（講師スライド・社内のデザインなど）も書く。案件の数だけでは負荷が見えないため
- 確認待ち・保留があれば「詰まり:」として1行
- MTDに何も無い人は「ここからは見えない」と書く。空いているとは書かない
- MTDだけの姿を全体だと思わせない。末尾に「MTDの外の仕事は入っていません」と添える
- 最後に「気づいたこと」を2〜3行（同じタスクが複数人に付いている、終わり際なのにMTD上で動きがない、など）
- 並び順はメンバー表のまま

## 6. アサイン候補（「〇月開始のWSのCCは誰がいい」）

条件（種別・開始時期・役割）を聞き取り、5のデータから**候補を2〜3人、理由つきで**出す。

```
1月開始のWS・CC の候補

  三上さん  今7案件。うち3件が12/4までに終了予定、1月に始まる予定の案件はなし。WSの経験9件
  山﨑さん  今走っている案件2、2か月先も続くのは1。WSの経験2件
  神山さん  今走っている案件2、来月から1件始まる。WSの経験2件

  ※ 小川さんはWSの経験が一番多い（12件）が、今10案件が並行し、2か月以内に2件始まる
  ※ シュバーニさん・松村さんはMTDに担当案件がなく、判断の材料がない
```

- 理由は**今いくつ並行していて、その時期までに終了・開始の予定がいくつあるか（MTDの日付）**と**同じ種別の経験**の2つ。
  事実だけを書き、「空くはず」「余裕がある」とは書かない
- 末尾に「日付の入っていない仕事や、MTDの外の仕事は入っていません」と添える
- 点数や順位は付けない。決めるのは管理者
- 経験が一番多い人を候補に挙げなかったときは、その人の並行数と予定（事実）を書く
- MTDに入っていない人は「材料がない」と書く。暇だと読まない
- MTDの外の案件（ミエタスクの要約）は、詳細の最後に「ミエタスクから（M/D 時点）」として分けて書く

## 書き方のルール

- **ミエタスクの件数は使わない。** 案件ごとに重さが違い、除外ルールも人ごとに違うので、状態も比較も読めない。
  比べてよいのは、全員同じ出どころ（MTDの案件の期間・種別）から出した数だけ
- ミエタスクから届くのは案件ごとの要約（案件名・状態・次の期限）だけ。タスクの題名・メモは届かない。推測で書かない
- 推測で埋めない。読み取れないものは「要確認」と書く
- 各節は最大5行。超えたら「…他N件」と明示する

## やらないこと

- Notion・Slackへの書き込み（タスクの完了・ステータス変更・投稿）
- 点数付け・順位付け
- 返信案や本人の下書きを出す
- メールで一致しない人を、名前の似た別人で埋める
