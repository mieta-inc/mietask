mietask を使える状態にする。**本人に質問しないで進める。** 本人にしてもらうのは、
コネクタの接続（未接続のときだけ）、Slack に届いた確認コードを入力すること、所属チームを選ぶことの3つだけ。
決められることはこちらで決める。

**鍵は一人ずつ別のもの。** 管理者に頼まなくても、確認コードで本人が受け取れる（管理台帳への登録もこのときに済む）。
確認コードはミエタスクの Bot から本人の Slack の DM にだけ届くので、本人しか入力できない。

所要5〜10分。途中で止まっても、もう一度 `/mietask:setup` と打てば続きから進む（作ったものは上書きしない）。

以下 `$B` = `${CLAUDE_PLUGIN_ROOT}/bin/mietask` とする。処理はすべてこの実行ファイルが受け持つ。
Mac でも Windows でも同じコマンドで動き、追加のインストールは要らない。**パスは必ず `"…"` で囲む。**

最初に本人へ一言伝える:

> セットアップを始めます。コマンドの実行許可を何度も聞かれないように、入力欄の下のモードを「Auto」にしておいてください。

---

## 0. 作業場所を確かめる

毎朝の実行（6 で作る定期タスク）は、**このセッションの作業場所で動く。** 作業場所が消えると、
毎朝の実行は何の知らせもなく止まる。フォルダを選ばずに始めたセッションの作業場所は一時フォルダで、
そのセッションを消すと一緒に消える。

```bash
pwd
```

パスに `scratch-workspaces` が**含まれていなければ**、そのまま 1 へ。

**含まれていたら一時フォルダ。** ほかの節に進まず、作業場所をミエタスクのデータ置き場に移す。

```bash
mkdir -p "$(bash "$B" paths home)"
bash "$B" paths home
```

本人に「作業場所を移す許可を求める画面が出たら、許可してください」と伝えてから、出てきた絶対パスを
作業場所を移す道具（`ToolSearch("change directory")` で出てくる `change_directory`）に渡す。
移るのは**このやり取りが終わったとき**なので、ここで止めて本人にこう伝える:

> 毎朝の実行が止まらないように、このセッションの作業場所をミエタスクのフォルダに移しました。
> **もう一度 `/mietask:setup` と打ってください。** そこから続けます。

作業場所を移す道具が無いときは、本人に「フォルダを選んで新しい会話を始め、そこで `/mietask:setup` と
打ってください」と伝えて止まる。**一時フォルダのまま 6 に進まない。**

## 1. もう入っているか見る

```bash
bash "$B" doctor
```

- ❌ も ⚠️ も無ければ、**すでに使える状態。** そう伝えて終わる（やり直さない）
- 「設定がありません」なら初回。2へ
- それ以外の ❌ は、その項目に対応する節だけをやり直す（鍵 → 3、投稿先 → 4）
- ⚠️ 自動更新 → `bash "$B" autoupdate` を実行する
- ⚠️ 毎朝の投稿 → 6 の定期タスクを確かめる。作業場所が消えていれば、0 の手順で移してから 6 で作り直す

## 2. コネクタを確かめる

巡回は Slack・Gmail・Googleカレンダーを**本人のアカウントで**読む。それぞれ1回ずつ実際に呼んで確かめる
（説明文を見るだけでは繋がっているか分からない）。

```
ToolSearch("slack search read user profile")
ToolSearch("gmail search threads")
ToolSearch("calendar list events")
```

ここで本人の情報を集める。**本人には聞かない。**

| | 取り方 |
|---|---|
| Slack ユーザーID | Slack の検索ツールの説明文にある `Current logged in user's user_id is U0…` |
| 名前 | Slack のプロフィール（表示名ではなく氏名。例: `山田 太郎`） |
| メール | Slack のプロフィール、または Gmail の自分宛てのメール |
| ワークスペース | Slack のパーマリンクのドメイン（`xxxx.slack.com` の `xxxx`） |

繋がっていないものがあれば、**何が繋がっていないか**と「設定のコネクタから接続してください」を伝えて止まる。
接続は本人が画面でやる操作なので、こちらからはできない。

## 3. 確認コードで鍵を受け取る

2で集めた値を渡す。**メールは Slack のプロフィールのもの**を渡す（管理台帳に入り、ページで本人を見分けるのに使う）。

```bash
bash "$B" enroll start --slack-id U0XXXXXXX --name "山田 太郎" --email name@example.com
```

- `鍵: すでに入っています` と出たら、この節は終わり。4へ
- `確認コード: … の Slack の DM に送りました` と出たら、本人にこう伝えて**ここで止まり、返事を待つ**:

> Slack に、ミエタスクから確認コード（6桁）を送りました。届いた番号を、このままここに入力してください（10分のあいだ有効です）。

本人が番号を入れたら、その番号を渡す:

```bash
bash "$B" enroll finish --code 123456
```

- `鍵: 保存しました` と出たら4へ。鍵はこのコマンドの中でファイルに保存されるだけで、**この会話にも出力にも出ない**
- `確認コードが違います（あと N 回）` → 本人に番号を見直してもらい、`enroll finish` をやり直す
- 期限切れ・回数切れ・「別の PC」と出たら → `enroll start` からやり直す
- `確認コードを Slack の DM で送れませんでした` → 2 の Slack ユーザーID を確かめ直す。それでも送れなければ、表示された内容を本人に伝えて管理者に確認してもらう
- `停止されています` → そこで止まり、そのまま本人に伝える（管理者に確認してもらう）
- `確認コードはもう Slack の DM に送っています` → 新しく送り直さず、届いている番号を入れてもらう

**確認コードは鍵ではない。** 本人が会話に打ってよい（10分で無効になり、申し込んだこの PC でしか使えない）。
確認コードを Slack ツールで読みに行かない（本人に入力してもらう）。

以前のやり方で、管理者から鍵が DM で届いている人は、確認コードの代わりに入力欄で鍵を貼ってもよい
（`bash "${CLAUDE_PLUGIN_ROOT}/scripts/token_prompt.sh"`。鍵の中身は画面に出さない・読み上げない・復唱しない）。

## 4. 設定と投稿先チャンネルを用意する

2で集めた値を渡す。**ここで設定ファイル・台帳・投稿先チャンネルがまとめてできる。**

```bash
bash "$B" setup --slack-id U0XXXXXXX --email name@example.com --name "山田 太郎" --workspace xxxx
```

- 投稿先の名前はメールから決まる（`ミエタスク-<名字>`。使われていれば名前も付ける。日本語が使えなければ英字）。本人には聞かない
- 本人を招待するところまでやる。**`招待しました` か `すでに参加しています` が出ていることを確かめる**
- 自動更新もここで入る。`自動更新: 入れました` か `すでに入っています` が出ていることを確かめる。
  入れられなかったときは、表示された理由を本人に伝える（直した版が届かなくなるため）
- 所属チームもここで表示される
- 「登録されていません」「停止されています」「鍵が無効です」と出たら、そこで止まり、そのまま本人に伝える（管理者に確認してもらう）
- 「この鍵は別の人のものです」と出たら、3 の確認コードからやり直す
- 既存の設定・台帳は上書きしない。別の人の設定が残っていれば止まる

エラーで止まったら、表示された内容を本人に伝える。`missing_scope` や `restricted_action` は
管理者側の設定の問題なので、無理に回避せず管理者に伝えてもらう。

### チームを選ぶ

```bash
bash "$B" teams
```

- `所属: …（すでに入っています…）` と出たら何もしない
- 一覧が出たら、**ここだけは本人に聞く。** 出てきた一覧を番号付きのまま見せて、番号で答えてもらう
  （選択肢が多いので、選択肢を出す道具は使わず会話で答えてもらう）:

> 所属しているチームを番号で選んでください。わからなければ「わからない」の番号で大丈夫です。

選ばれた番号の行の右端の ID を渡す（「わからない」なら `none`）:

```bash
bash "$B" join-team pm1
```

入ったら本人に伝える:

> 〇〇に入りました。あなたの持ち案件が、このチームの管理者のページに出るようになります。違っていたら、システム管理者に伝えてください。

## 5. 最初のあいさつを投稿する

本人のプライベートチャンネルなので、聞かずに投稿してよい。

```bash
bash "$B" paths tmp
```

出てきたフォルダに `hello.json` を **Writeツールで** 書く（パスは出力の絶対パスを使う。`~` は使わない）:

```json
{"parent": ":wave: ミエタスクのセットアップが終わりました。平日の朝、ここに今日の一覧が届きます。", "replies": []}
```

```bash
bash "$B" post --payload "<tmpの絶対パス>/hello.json"
```

届いたことを Slack で見てもらう。届かなければ `bash "$B" doctor` を実行して、❌ の行を伝える。

## 6. 毎朝動くようにする

**0 を通ったあとで作る**（作業場所が一時フォルダのまま作ると、そのセッションを消した日から止まる）。

`scheduled-tasks` のツールで定期タスクを作る。**時刻は聞かずに平日7時にする**（変えたいと言われたら変える）。

```
ToolSearch("create scheduled task")
```

- taskId: `mietask-daily`
- title: `ミエタスク（毎朝）`
- cron: `0 7 * * 1-5`
- prompt: 「mietask プラグインの task-daily スキルを使って、Slack・Gmail・Googleカレンダーを巡回し、自分のミエタスクのチャンネルに今日の一覧を投稿する。前日のスレッドへの返信（完了・ステイ・メモ・追加）も反映する」

**結果に、Auto モードで保存されたかが出る。** Auto で保存されていなければ、朝の実行が許可待ちで止まり、
投稿が届かない。その場合は本人に「入力欄の下のモードを Auto にしてください」と伝え、切り替わったら
同じ taskId で作り直す（`update_scheduled_task` で中身を同じにして保存し直す）。

本人に伝える:

> 毎朝の実行は Claude のアプリが開いているあいだに動きます。7時に閉じていれば、次に開いたときに届きます。

## 7. 最初の1回を回す

その場で `task-daily` スキルを使い、**実際に巡回して投稿する。** 明日まで待たせない。

## 8. 最後に伝えること

**これは必ず言う。**

> **最初の1週間で、自分用に育てていくものです。**
> はじめは何も覚えていない状態なので、通知メールを拾ったり、対応済みのものを出したりします。
> 要らないものが出たら、Claude に「これは要らない」「〇〇からのメールは出さなくていい」と言ってください。
> 次から出なくなり、だんだん自分に合った一覧になっていきます。
>
> その日の投稿に返信すると、翌朝の一覧に反映されます。書き方は「番号のあとに続けて書く」だけです。
> - `1完了` → もう出ません
> - `2ステイ` → 明日もそのまま出します
> - `3 山田さんに電話済み` → メモとして翌朝に出ます
> - `追加 見積書を作る 11/20まで` → 新しいタスクとして足します（Slackや議事録に出てこない仕事はここから）
>
> 調子がおかしいときは「ミエタスクを診断して」と言ってください。

続けてこれも必ず言う。

> **一覧の中身（タスクの題名・メモ・どこから来たか）は、このチャンネルの外には出ません。**
> チームの管理者に届くのは、**持っている案件の一覧**（案件名・関わり方・動いている／相手待ち／しばらく動きなし・段階・次の節目・いまの状態の一言と数行の詳細・最後に動いた日）だけです。
> 一覧は毎朝、動きのあった案件だけ更新されます。終わった案件は「〇〇は終わった」と言えば外れます（3週間動きが無ければ「しばらく動きなし」、6週間で自動で外れます）。
> 何が届いているかは、社内のミエタスクのページの「自分」で、いつでも確かめられます。
> 出したくない案件があれば「〇〇は管理者に出さないで」と言ってください。
> 動いているかどうか（最後に動いた日時と、毎朝の件数）は、システム管理者が動作の点検のために見ることがあります。

## やらないこと

- **鍵の中身を表示・復唱・ログ出力しない**
- 確認コードを Slack ツールで読みに行かない（本人に入力してもらう）
- 本人に質問して進めない（コネクタの接続・確認コードの入力・チームの選択だけをお願いする）
- 既存の `config.json` / `tasks.json` / `state.json` を上書きしない
- 本人のチャンネル以外に投稿しない
- コネクタの接続を代わりにやろうとしない。できない
- 繋がらなかったものを黙って飛ばさない。**何が繋がっていないか必ず言う**
