mietask を使える状態にする。**本人に質問しないで進める。** 本人にしてもらうのは、
コネクタの接続（未接続のときだけ）、Slack に届いた確認コードを入力すること、所属チームを選ぶことの3つだけ。
決められることはこちらで決める。

**鍵は一人ずつ別のもの。** 管理者に頼まなくても、確認コードで本人が受け取れる（管理台帳への登録もこのときに済む）。
確認コードはミエタスクの Bot から本人の Slack の DM にだけ届くので、本人しか入力できない。

所要10〜15分（最初の巡回に5〜10分）。途中で止まっても、もう一度 `/mietask:setup` と打てば続きから進む（作ったものは上書きしない）。

処理はすべて実行ファイル `${CLAUDE_PLUGIN_ROOT}/bin/mietask` が受け持つ。
Mac でも Windows でも同じコマンドで動き、追加のインストールは要らない。**パスは必ず `"…"` で囲む。**

**コマンドの打ち方（毎朝の実行が確認画面で止まらないように）**

- 実行ファイルは毎回 `bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" <コマンド> [引数]` と、パスをそのまま書いて呼ぶ。`B=…` のように変数に入れない
- 1回の Bash で打つのは1つのコマンドだけ。`;` `&&` `|` でつながない。`cd` もしない
- 台帳や設定を `cat`・`python3` などで直接読まない。中身は実行ファイルの出力と Read ツールで見る
- 自動承認モードが使えない会社でも、この形だけは許可に登録してある（`mietask permissions`）。
  外れた形で打つと確認画面で止まり、朝の投稿が届かない

最初に本人へ一言伝える:

> ミエタスクのセットアップを始めます。10分ほどで終わります。
> お願いするのは、Slack に届く確認コードを入れることと、所属チームを選ぶことの2つだけです。あとはこちらで進めます。
> 途中で何度か、操作の許可を求める画面が出ます。そのたびに「許可」を押してください。
> 毎朝の実行では出ないように、ミエタスクが使う操作だけをセットアップの中で許可に登録します。

## 0. 作業場所を確かめる

毎朝の実行（6 で作る定期タスク）は、**このセッションの作業場所で動く。** 作業場所が消えると、
毎朝の実行は何の知らせもなく止まる。フォルダを選ばずに始めたセッションの作業場所は一時フォルダで、
そのセッションを消すと一緒に消える。

```bash
pwd
```

パスに `scratch-workspaces` が**含まれていなければ**、そのまま 1 へ。

**含まれていたら一時フォルダ。** ほかの節に進まず、作業場所をミエタスクのデータ置き場に移す。

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" paths home
```

出てきた絶対パスのフォルダが無ければ作る（`mkdir -p "<出てきた絶対パス>"`）。

本人に「作業場所を移す許可を求める画面が出たら、許可してください」と伝えてから、出てきた絶対パスを
作業場所を移す道具（`ToolSearch("change directory")` で出てくる `change_directory`）に渡す。
移るのは**このやり取りが終わったとき**なので、ここで止めて本人にこう伝える:

> 毎朝の実行が止まらないように、このセッションの作業場所をミエタスクのフォルダに移しました。
> **もう一度 `/mietask:setup` と打ってください。** そこから続けます。

作業場所を移す道具が無いときは、本人に「フォルダを選んで新しい会話を始め、そこで `/mietask:setup` と
打ってください」と伝えて止まる。**一時フォルダのまま 6 に進まない。**

## 1. もう入っているか見る

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" doctor
```

- ❌ も ⚠️ も無ければ、**すでに使える状態。** そう伝えて終わる（やり直さない）
- 「設定がありません」なら初回。2へ
- それ以外の ❌ は、その項目に対応する節だけをやり直す（鍵 → 3、投稿先 → 4）
- ⚠️ 自動更新 → `bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" autoupdate` を実行する
- ⚠️ 許可 → 2 でコネクタの道具の名前を集めてから、6 の「許可を登録する」だけをやる
- ⚠️ 毎朝の投稿 → 6 の定期タスクを確かめる。作業場所が消えていれば、0 の手順で移してから 6 で作り直す

## 2. コネクタを確かめる

巡回は Slack・Gmail・Googleカレンダーを**本人のアカウントで**読む。それぞれ1回ずつ実際に呼んで確かめる
（説明文を見るだけでは繋がっているか分からない）。

```
ToolSearch("slack search read user profile")
ToolSearch("gmail search threads")
ToolSearch("calendar list events")
```

ここで本人の情報を集める。**本人には聞かない。**

| | 取り方 |
|---|---|
| Slack ユーザーID | Slack の検索ツールの説明文にある `Current logged in user's user_id is U0…` |
| 名前 | Slack のプロフィール（表示名ではなく氏名。例: `山田 太郎`） |
| メール | Slack のプロフィール、または Gmail の自分宛てのメール |
| ワークスペース | Slack のパーマリンクのドメイン（`xxxx.slack.com` の `xxxx`） |
| 読み取りの道具の名前 | 下の表の道具の、`mcp__` から始まる正式な名前（6 で許可に登録する）。ToolSearch の結果やツール一覧にある名前をそのまま控える |

| コネクタ | 控える道具（名前の最後の部分） |
|---|---|
| Slack | `slack_read_thread` `slack_read_channel` `slack_read_user_profile` `slack_search_public` `slack_search_public_and_private` `slack_search_channels` `slack_search_users` |
| Gmail | `search_threads` `get_thread` `list_labels` |
| Googleカレンダー | `list_events` `get_event` `list_calendars` |
| Googleドライブ（つないでいれば） | `list_recent_files` `search_files` `get_file_metadata` `read_file_content` |

**送信・作成・削除の道具は控えない。** 許可に入れるのは読み取りだけ（実行ファイルも、読み取り以外は受け付けない）。

繋がっていないものがあれば、**何が繋がっていないか**を入れて、本人にこう伝えて止まる:

> 〇〇がまだ Claude につながっていません。Claude の設定の「コネクタ」で〇〇の「接続」を押し、自分の会社のアカウントで許可してください。
> つないだら、もう一度 `/mietask:setup` と打ってください。続きから進めます。

接続は本人が画面でやる操作なので、こちらからはできない。

## 3. 確認コードで鍵を受け取る

2で集めた値を渡す。**メールは Slack のプロフィールのもの**を渡す（管理台帳に入り、ページで本人を見分けるのに使う）。

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" enroll start --slack-id U0XXXXXXX --name "山田 太郎" --email name@example.com
```

- `鍵: すでに入っています` と出たら、この節は終わり。4へ
- `確認コード: … の Slack の DM に送りました` と出たら、本人にこう伝えて**ここで止まり、返事を待つ**:

> Slack に、ミエタスクから確認コード（6桁）を送りました。Slack の左側の「アプリ」にある「ミエタスク」の DM に届いています。
> 届いた番号を、このままここに入力してください（10分のあいだ有効です）。

本人が番号を入れたら、その番号を渡す:

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" enroll finish --code 123456
```

- `鍵: 保存しました` と出たら4へ。鍵はこのコマンドの中でファイルに保存されるだけで、**この会話にも出力にも出ない**
- `確認コードが違います（あと N 回）` → 本人に番号を見直してもらい、`enroll finish` をやり直す
- 期限切れ・回数切れ・「別の PC」と出たら → `enroll start` からやり直す
- `確認コードを Slack の DM で送れませんでした` → 2 の Slack ユーザーID を確かめ直す。それでも送れなければ、表示された内容を本人に伝えて管理者に確認してもらう
- `停止されています` → そこで止まり、そのまま本人に伝える（管理者に確認してもらう）
- `確認コードはもう Slack の DM に送っています` → 新しく送り直さず、届いている番号を入れてもらう

**確認コードは鍵ではない。** 本人が会話に打ってよい（10分で無効になり、申し込んだこの PC でしか使えない）。
確認コードを Slack ツールで読みに行かない（本人に入力してもらう）。

以前のやり方で、管理者から鍵が DM で届いている人は、確認コードの代わりに入力欄で鍵を貼ってもよい
（`bash "${CLAUDE_PLUGIN_ROOT}/scripts/token_prompt.sh"`。鍵の中身は画面に出さない・読み上げない・復唱しない）。

## 4. 設定と投稿先チャンネルを用意する

2で集めた値を渡す。**ここで設定ファイル・台帳・投稿先チャンネルがまとめてできる。**

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" setup --slack-id U0XXXXXXX --email name@example.com --name "山田 太郎" --workspace xxxx
```

- 投稿先の名前はメールから決まる（`ミエタスク-<名字>`。使われていれば名前も付ける。日本語が使えなければ英字）。本人には聞かない
- 本人を招待するところまでやる。**`招待しました` か `すでに参加しています` が出ていることを確かめる**。確かめたら本人にこう伝える:

> あなた専用のチャンネル「#（出てきたチャンネル名）」を作って招待しました。Slack で開いてみてください。あなたと Bot だけが見られるチャンネルです。
- 自動更新もここで入る。`自動更新: 入れました` か `すでに入っています` が出ていることを確かめる。
  入れられなかったときは、表示された理由を本人に伝える（直した版が届かなくなるため）
- 所属チームもここで表示される
- 「登録されていません」「停止されています」「鍵が無効です」と出たら、そこで止まり、そのまま本人に伝える（管理者に確認してもらう）
- 「この鍵は別の人のものです」と出たら、3 の確認コードからやり直す
- 既存の設定・台帳は上書きしない。別の人の設定が残っていれば止まる

エラーで止まったら、表示された内容を本人に伝える。`missing_scope` や `restricted_action` は
管理者側の設定の問題なので、無理に回避せず管理者に伝えてもらう。

### チームを選ぶ

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" teams
```

- `所属: …（すでに入っています…）` と出たら何もしない
- 一覧が出たら、**ここだけは本人に聞く。** 出てきた一覧を番号付きのまま見せて、番号で答えてもらう
  （選択肢が多いので、選択肢を出す道具は使わず会話で答えてもらう）:

> 所属しているチームを番号で選んでください。わからなければ「わからない」の番号で大丈夫です（あとでシステム管理者が直します）。
> 選んだチームの管理者には、あなたが持っている案件の一覧（案件名と、いまの状態）が見えるようになります。タスクの中身やメール・DM は見えません。

選ばれた番号の行の右端の ID を渡す（「わからない」なら `none`）:

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" join-team pm1
```

入ったら本人に伝える:

> 〇〇に入りました。あなたの持ち案件が、このチームの管理者のページに出るようになります。違っていたら、システム管理者に伝えてください。

## 5. 最初のあいさつを投稿する

本人のプライベートチャンネルなので、聞かずに投稿してよい。

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" paths tmp
```

出てきたフォルダに `hello.json` を **Writeツールで** 書く（パスは出力の絶対パスを使う。`~` は使わない）:

```json
{"pin": true, "parent": ":wave: *ミエタスクへようこそ*\n平日の朝7時ごろ、ここに今日やることの一覧が届きます。このチャンネルはあなたと Bot だけが見られます。\n• 一覧の投稿に返信すると、翌朝に反映されます：`1完了` `2ステイ` `3 メモ` `追加 〇〇 11/20まで`\n• 終わったこと・要望（「〇〇からのメールは要らない」など）も、一覧のスレッドにそのまま書けば翌朝から反映します。一覧が自分に合わせて育っていきます", "replies": []}
```

この文面は変えずにそのまま使う（チャンネルの最初のメッセージが、本人の使い方の手引きになる）。
`"pin": true` で、このメッセージはチャンネルにピン留めされる。`--no-team` は点検用の件数を送らない指定（あいさつには件数が無いので、送るとその日の件数が0で上書きされる）。`ピン留めできませんでした` と出ても投稿は済んでいるので、やり直さず先へ進む。

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" post --payload "<tmpの絶対パス>/hello.json" --no-team
```

届いたことを Slack で見てもらう。届かなければ `bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" doctor` を実行して、❌ の行を伝える。

## 6. 毎朝動くようにする

**0 を通ったあとで作る**（作業場所が一時フォルダのまま作ると、そのセッションを消した日から止まる）。

### 許可を登録する

会社の設定で自動承認（Auto）モードが使えないことがある。そのままだと、毎朝の実行が確認画面で止まって投稿が届かない。
ミエタスクが使う操作だけを許可に登録しておく。2 で控えた読み取りの道具の名前を `,` でつないで渡す:

```bash
bash "${CLAUDE_PLUGIN_ROOT}/bin/mietask" permissions --tools mcp__xxxx__slack_read_thread,mcp__xxxx__slack_read_channel,mcp__yyyy__search_threads,…
```

- 実行ファイル・`~/.mietask` の読み書き・ミエタスクのスキルは、4 の `setup` で登録済み。ここで足すのはコネクタの道具
- `許可: N件を足しました` か `すでに入っています` が出れば済み
- 「読み取りの道具ではないので、許可に入れません」と出たら、その名前を外してやり直す
- 本人の Claude の設定（`~/.claude/settings.json`）に足すだけで、ほかの設定は変えない。書き換える前に控え（`settings.json.bak-mietask`）を取る

### 定期タスクを作る

`scheduled-tasks` のツールで定期タスクを作る。**時刻は聞かずに平日7時にする**（変えたいと言われたら変える）。

```
ToolSearch("create scheduled task")
```

- taskId: `mietask-daily`
- title: `ミエタスク（毎朝）`
- cron: `0 7 * * 1-5`
- prompt: 「mietask プラグインの task-daily スキルを使って、Slack・Gmail・Googleカレンダーを巡回し、自分のミエタスクのチャンネルに今日の一覧を投稿する。前日のスレッドへの返信（完了・ステイ・メモ・追加）も反映する」

モードは Auto でなくてよい。登録した許可の範囲なら、毎朝の実行で確認画面は出ない。

本人に伝える:

> 毎朝の実行は Claude のアプリが開いているあいだに動きます。7時に閉じていれば、次に開いたときに届きます。

## 7. 最初の1回を回す

回す前に、本人にこう伝える:

> 手始めに、直近2週間の分を巡回してチャンネルに入れますね。最初の1回はていねいに見るので、5〜10分かかります。

その場で `task-daily` スキルを使い、**実際に巡回して投稿する。** 明日まで待たせない。

届いたら、本人にこう伝える:

> 届いた一覧を見て、要らないものがあれば「これは要らない」と言ってください。次の朝から出なくなります。

投稿に「これも持っている案件ですか？」の子スレッドを付けたときは、続けてこう伝える:

> スレッドの最後に、持っているか分からなかった案件を並べました。持っているものがあれば「〇〇も持っている」と言ってください。

言われたら、その場で `task-daily` の会話の表どおりに `projects update` で足す。

## 8. 最後に伝えること

**これは必ず言う。**

> **最初の1週間で、自分用に育てていくものです。**
> はじめは何も覚えていない状態なので、通知メールを拾ったり、対応済みのものを出したりします。
> 要らないものが出たら、Claude に「これは要らない」「〇〇からのメールは出さなくていい」と言ってください。
> 次から出なくなり、だんだん自分に合った一覧になっていきます。
>
> その日の投稿に返信すると、翌朝の一覧に反映されます。書き方は「番号のあとに続けて書く」だけです。
> - `1完了` → もう出ません
> - `2ステイ` → 明日もそのまま出します
> - `3 山田さんに電話済み` → メモとして翌朝に出ます
> - `追加 見積書を作る 11/20まで` → 新しいタスクとして足します（Slackや議事録に出てこない仕事はここから）
>
> この形に合わなくても大丈夫です。「見積書、出しました」「〇〇からのメールは要らない」「出欠確認は出さなくていい」のように、
> 終わったことや要望をそのまま書いておけば、翌朝の Claude が読んで反映し、何をしたかをスレッドで知らせます。
>
> 朝の一覧が届かないなど調子がおかしいときは、Claude にそのまま伝えてください（例：「今朝ミエタスクの一覧が届いていない」）。

続けてこれも必ず言う。

> **一覧の中身（タスクの題名・メモ・どこから来たか）は、このチャンネルの外には出ません。**
> チームの管理者に届くのは、**持っている案件の一覧**（案件名・関わり方・動いている／相手待ち／しばらく動きなし・段階・次の節目・いまの状態の一言と数行の詳細・最後に動いた日）だけです。
> 一覧は毎朝、動きのあった案件だけ更新されます。終わった案件は「〇〇は終わった」と言えば外れます（3週間動きが無ければ「しばらく動きなし」、6週間で自動で外れます）。
> 何が届いているかは、社内のミエタスクのページの「自分」で、いつでも確かめられます。
> 出したくない案件があれば「〇〇は管理者に出さないで」と言ってください。
> 動いているかどうか（最後に動いた日時と、毎朝の件数）は、システム管理者が動作の点検のために見ることがあります。

## やらないこと

- **鍵の中身を表示・復唱・ログ出力しない**
- 確認コードを Slack ツールで読みに行かない（本人に入力してもらう）
- 本人に質問して進めない（コネクタの接続・確認コードの入力・チームの選択だけをお願いする）
- 既存の `config.json` / `tasks.json` / `state.json` を上書きしない
- 本人のチャンネル以外に投稿しない
- コネクタの接続を代わりにやろうとしない。できない
- 繋がらなかったものを黙って飛ばさない。**何が繋がっていないか必ず言う**
