# mietask

毎朝、Slack・Gmail・Googleカレンダーを巡回して、**自分が対応すべきことだけ**を
自分専用のSlackチャンネルに投稿する（チームに入っていれば、そのまとめチャンネルにも出る）。
投稿に「1完了」「2ステイ」「3 メモ」と返信すると、
翌朝の巡回がそれを読んで台帳に反映する。

```
:date: 11/13(金) 07:00  ⚠超過2 / 🔴今日3 / 🟡今週7

1. 見積書を確認して返信 ← 2日超過
2. 定例の資料を用意する
3. 〇〇さんへ返信

詳細はスレッドに。終わったものは「1完了」と返信してください。
```

朝は親メッセージだけ見れば済む。中身は子スレッドに畳んである。

## 必要なもの

| | |
|---|---|
| Claude Code | 有料プランに入っていれば使える |
| Slack・Gmail・Googleカレンダーの接続 | Claude Codeの設定から各自で繋ぐ |
| ミエタスクの鍵 | 一人ずつ別の鍵。管理者が管理台帳で発行すると、ミエタスクの Bot から DM で届く（Botトークンはメンバーに配らない） |
| ほかのソフト | 要らない。処理は Mac・Windows 用の実行ファイル（`plugins/mietask/bin/`）が受け持つ |

**巡回は本人のアカウントで動く。** 他人のMacから代わりに回すことはできない。

## 入れ方

**1. マーケットプレイスを追加する**

Claude の設定（カスタマイズ）からマーケットプレイスを追加し、GitHubリポジトリに
`mieta-inc/mietask` を指定する。

**2. プラグインをこのコンピュータに追加する**

追加したマーケットプレイスの中の `mietask` を入れる。

**3. セットアップする**

入力欄の下のモードを「Auto」にしてから（毎朝の実行が許可待ちで止まらないように）、
こう打つ。

```
/mietask:setup
```

あとは**入力欄に鍵を貼るだけ。** 質問はされない。5〜10分で終わる。

- チャンネルはBotが自分で作る（名前はメールから決まる `ミエタスク-<名字>`）。`/invite` もIDのコピーも要らない
- 管理台帳に所属チームが入っていれば、**チームのまとめチャンネルへの投稿もここで一緒に始まる**
- 最後にその場で1回巡回して投稿するので、どんなものが届くかすぐ見られる

### 先にやっておくこと

**Slack・Gmail・Googleカレンダーを Claude Code に繋いでおく。**
巡回は本人のアカウントで読むので、ここが繋がっていないと始まらない。
セットアップの最初で確認し、繋がっていなければそこで止まる。

### 更新を受け取れるようにする

**既定では自動更新されない。** 自動なのは Anthropic 公式のマーケットプレイスだけで、
社内のものは自分で有効にする必要がある。入れておかないと、新しい版を出しても手元は古いまま
になり、直したはずの不具合がいつまでも残る。

`~/.claude/settings.json` の `extraKnownMarketplaces` にある `mieta-tools` に、
`"autoUpdate": true` を足す（`source` はマーケットプレイスを追加したときに入っている）。

```json
"extraKnownMarketplaces": {
  "mieta-tools": {
    "source": { "source": "git", "url": "https://github.com/mieta-inc/mietask.git" },
    "autoUpdate": true
  }
}
```

有効にすると、最初のメッセージを送ってから10分以内に更新が走る。動いているセッションは
そのままで、次に開いたときから新しい版になる。

## 使い方

| したいこと | やること |
|---|---|
| 今すぐタスクを見たい | 「タスク確認」と打つ |
| 終わったことを伝える | その日のスレッドに「3完了」と返信（翌朝に反映） |
| 明日もそのまま出してほしい | 「2ステイ」と返信 |
| 状況をメモしておく | 「3 山田さんに電話済み」と返信。翌朝「前回のメモ」として出る |
| 巡回で拾えない仕事を足す | 「追加 見積書を作る 11/20まで」と返信。翌朝から一覧に出る（日付があれば期限になる） |
| 番号を間違えそう | 「t091完了」とIDで返してもよい |
| 今週はやらないことにした | 「3は来週にする」と言う |
| もう出さなくていい | 「これは対応不要」と言う |

完了の返信は**まとめて書いても、1件ずつ返しても、後から編集して足してもよい。**
翌朝にスレッド全体を読むので、その時点の最終形が効く。

```
3完了
4完了
5完了
```

**注意:** 翌朝の巡回が走ったあとで古いスレッドに追記しても読まれない。
その日のスレッドに返信する。

## 最初の1週間で自分用に育てる

除外ルールが空の状態から始まるので、最初は通知メールを拾ったり、対応済みのものを
出したりする。**これは想定どおり。** 次のどちらかで直していくと、自分に合った一覧になっていく。

- 「これは要らない」と言う → 次から出なくなる
- `~/.mietask/config.json` の `exclude_senders` に送信元を足す

## 置き場所

| | パス |
|---|---|
| 設定 | `~/.mietask/config.json` |
| タスク台帳 | `~/.mietask/data/tasks.json` |
| 鍵（Botトークン） | `~/.config/mietask/slack-token` |

**台帳は手で編集しない。** `mietask sync` を通す（バックアップが入っている）。
壊れたら `data/tasks.json.bak_*`（直近30件）から戻せる。

データの場所を変えたい場合は環境変数 `MIETASK_HOME` で指定する。
**トークンだけは同期フォルダに置かない。**

## Slack Appを作る（自分のワークスペースで使う場合）

社内で使う場合はアプリが用意済みなので、この節は不要。

1. https://api.slack.com/apps で Create New App → From scratch
2. OAuth & Permissions → Bot Token Scopes に **`chat:write`**・**`chat:write.customize`**・**`groups:write`**・**`groups:read`** を追加
3. Install to Workspace
4. **Bot User OAuth Token**（`xoxb-` で始まる）をコピー
5. 投稿したいチャンネルで `/invite @アプリ名`

この4つだけでよい。`groups:write` はチャンネルの作成と招待、`groups:read` は
「本人がそのチャンネルに入っているか」の確認、`chat:write.customize` は
投稿時の表示名とアイコンの指定に使う。

## よくある詰まり

| 症状 | 原因 |
|---|---|
| `not_in_channel` | チャンネルに `/invite` していない |
| `missing_scope` | 必要なスコープが付いていない |
| 送信者名が古いまま | 過去の投稿は変わらない。Slackは投稿時の名前を記録する |
| `invalid_auth` | トークンが違う。`xoxp-` ではなく `xoxb-` |
| 朝に届かない | その時刻にClaude Codeが閉じていた。次に開いた時に届く |
| 「N完了」が効かない | 前日の `record` が走っていない。`mietask sync thread` で確認 |
| どこが悪いか分からない | Claude に「ミエタスクを診断して」と言う（`mietask doctor`） |
| 「管理台帳で停止されています」 | 管理者が台帳で停止にしている。管理者に確認する |

## チャンネルは一人に1つ

チャンネル名は**ワークスペース全体で一意**なので、全員が同じ名前にはできない。
既定は `ミエタスク-<名字>`（例 `ミエタスク-yamada`）。同じ名字がすでにあれば `ミエタスク-shino-yamada` のように名前も付ける。

同じ名前がすでにある場合、**セットアップは黙ってそれを使わずに止まる。**
他人のチャンネルに自分のタスクを流さないため。別の名前にするか、
自分のものだと確認できたIDを渡す。

できたチャンネルには**本人とBotしかいない。** 他の人は入れないこと。

## 投稿先は2か所だけ

タスクには顧客名や社内の依頼内容がそのまま入る。だから投稿先は決まった2か所に絞ってある。

| 投稿先 | 見られる人 | 中身 |
|---|---|---|
| 自分のチャンネル | 本人だけ（とBot） | 一覧の全部。返信案も入る |
| 所属チームのまとめチャンネル | そのチームの管理者 | 返信案と本人向けの案内を外した一覧。親に名前が付く |

- **まとめチャンネルにメンバーは入れない。** メンバー同士がお互いの一覧を見ることはない
- まとめに出るのは、管理台帳でチームに入っている人だけ。チームに入っていなければ自分のチャンネルにだけ出る
- この2か所以外には出せない。窓口（管理台帳の Apps Script）が、本人の投稿先と所属チームのまとめ以外への投稿を断る

返信案は作るが、**送信はしない。** 送るかどうかは必ず自分で決める。

### 管理者が気をつけること

- まとめチャンネルに入れるのは、台帳の「チーム」シートの管理者だけにする（メニューの「選んだチームの管理者をまとめチャンネルに招待する」）
- 管理者が替わったら、前の管理者は **Slack の画面から手で外す。** Bot は人を外せないので、放っておくと見え続ける
- 導入してもらう前に、**一覧がチームのまとめにも出ること**を本人に伝えておく
