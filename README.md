# mietask

毎朝、Slack・Gmail・Googleカレンダーを巡回して、**自分が対応すべきことだけ**を
自分専用のSlackチャンネルに投稿する（一覧の中身はほかの誰にも届かない。管理者に届くのは案件ごとの状態と一言だけ）。
投稿に「1完了」「2ステイ」「3 メモ」と返信すると、
翌朝の巡回がそれを読んで台帳に反映する。

```
:date: 11/13(金) 07:00  ⚠超過2 / 🔴今日3 / 🟡今週7

1. 見積書を確認して返信 ← 2日超過
2. 定例の資料を用意する
3. 〇〇さんへ返信

詳細はスレッドに。終わったものは「1完了」と返信してください。
```

朝は親メッセージだけ見れば済む。中身は子スレッドに畳んである。

## 必要なもの

| | |
|---|---|
| Claude Code | 有料プランに入っていれば使える |
| Slack・Gmail・Googleカレンダーの接続 | Claude Codeの設定から各自で繋ぐ |
| ミエタスクの鍵 | 一人ずつ別の鍵。管理者が管理台帳で発行すると、ミエタスクの Bot から DM で届く（Botトークンはメンバーに配らない） |
| ほかのソフト | 要らない。処理は Mac・Windows 用の実行ファイル（`plugins/mietask/bin/`）が受け持つ |

**巡回は本人のアカウントで動く。** 他人のMacから代わりに回すことはできない。

## 入れ方

**1. マーケットプレイスを追加する**

Claude の設定（カスタマイズ）からマーケットプレイスを追加し、GitHubリポジトリに
`mieta-inc/mietask` を指定する。

**2. プラグインをこのコンピュータに追加する**

追加したマーケットプレイスの中の `mietask` を入れる。

**3. セットアップする**

入力欄の下のモードを「Auto」にしてから（毎朝の実行が許可待ちで止まらないように）、
こう打つ。フォルダを選ばずに始めた会話なら、セットアップが最初に作業場所をミエタスクのフォルダに移すので、
言われたとおりもう一度打つ（一時フォルダのままだと、その会話を消した日から毎朝の実行が止まるため）。

```
/mietask:setup
```

あとは**入力欄に鍵を貼るだけ。** 質問はされない。5〜10分で終わる。

- チャンネルはBotが自分で作る（名前はメールから決まる `ミエタスク-<名字>`）。`/invite` もIDのコピーも要らない
- 一覧の中身は、チームの管理者を含めてほかの誰にも届かない。管理者に届くのは持っている案件の一覧（案件名・関わり方・状態・段階・次の節目・いまの状態の一言と詳細・最後に動いた日）だけで、同じものが自分のチャンネルにも出る
- 自動更新もここで入る（下の「更新を受け取れるようにする」を手でやる必要はない）
- 最後にその場で1回巡回して投稿するので、どんなものが届くかすぐ見られる

### 先にやっておくこと

**Slack・Gmail・Googleカレンダーを Claude Code に繋いでおく。**
巡回は本人のアカウントで読むので、ここが繋がっていないと始まらない。
セットアップの最初で確認し、繋がっていなければそこで止まる。

### 更新を受け取れるようにする

**セットアップで自動的に入る。** 入っているかは「ミエタスクを診断して」で分かる。
入っていないと出たら、Claude に「ミエタスクの自動更新を入れて」と言えば入る（`mietask autoupdate`）。
以下は、手で入れる場合の説明。

**既定では自動更新されない。** 自動なのは Anthropic 公式のマーケットプレイスだけで、
社内のものは自分で有効にする必要がある。入れておかないと、新しい版を出しても手元は古いまま
になり、直したはずの不具合がいつまでも残る。

`~/.claude/settings.json` の `extraKnownMarketplaces` にある `mieta-tools` に、
`"autoUpdate": true` を足す（`source` はマーケットプレイスを追加したときに入っている）。

```json
"extraKnownMarketplaces": {
  "mieta-tools": {
    "source": { "source": "git", "url": "https://github.com/mieta-inc/mietask.git" },
    "autoUpdate": true
  }
}
```

有効にすると、最初のメッセージを送ってから10分以内に更新が走る。動いているセッションは
そのままで、次に開いたときから新しい版になる。

## 使い方

| したいこと | やること |
|---|---|
| 今すぐタスクを見たい | 「タスク確認」と打つ |
| 終わったことを伝える | その日のスレッドに「3完了」と返信（翌朝に反映） |
| 明日もそのまま出してほしい | 「2ステイ」と返信 |
| 状況をメモしておく | 「3 山田さんに電話済み」と返信。翌朝「前回のメモ」として出る |
| 巡回で拾えない仕事を足す | 「追加 見積書を作る 11/20まで」と返信。翌朝から一覧に出る（日付があれば期限になる） |
| 番号を間違えそう | 「t091完了」とIDで返してもよい |
| 今週はやらないことにした | 「3は来週にする」と言う |
| もう出さなくていい | 「これは対応不要」と言う |

完了の返信は**まとめて書いても、1件ずつ返しても、後から編集して足してもよい。**
翌朝にスレッド全体を読むので、その時点の最終形が効く。

```
3完了
4完了
5完了
```

**注意:** 翌朝の巡回が走ったあとで古いスレッドに追記しても読まれない。
その日のスレッドに返信する。

## 最初の1週間で自分用に育てる

除外ルールが空の状態から始まるので、最初は通知メールを拾ったり、対応済みのものを
出したりする。**これは想定どおり。** 次のどちらかで直していくと、自分に合った一覧になっていく。

- 「これは要らない」と言う → 次から出なくなる
- `~/.mietask/config.json` の `exclude_senders` に送信元を足す

## 置き場所

| | パス |
|---|---|
| 設定 | `~/.mietask/config.json` |
| タスク台帳 | `~/.mietask/data/tasks.json` |
| 鍵（Botトークン） | `~/.config/mietask/slack-token` |

**台帳は手で編集しない。** `mietask sync` を通す（バックアップが入っている）。
壊れたら `data/tasks.json.bak_*`（直近30件）から戻せる。

データの場所を変えたい場合は環境変数 `MIETASK_HOME` で指定する。
**トークンだけは同期フォルダに置かない。**

## Slack Appを作る（自分のワークスペースで使う場合）

社内で使う場合はアプリが用意済みなので、この節は不要。

1. https://api.slack.com/apps で Create New App → From scratch
2. OAuth & Permissions → Bot Token Scopes に **`chat:write`**・**`chat:write.customize`**・**`groups:write`**・**`groups:read`** を追加
3. Install to Workspace
4. **Bot User OAuth Token**（`xoxb-` で始まる）をコピー
5. 投稿したいチャンネルで `/invite @アプリ名`

この4つだけでよい。`groups:write` はチャンネルの作成と招待、`groups:read` は
「本人がそのチャンネルに入っているか」の確認、`chat:write.customize` は
投稿時の表示名とアイコンの指定に使う。

## よくある詰まり

| 症状 | 原因 |
|---|---|
| `not_in_channel` | チャンネルに `/invite` していない |
| `missing_scope` | 必要なスコープが付いていない |
| 送信者名が古いまま | 過去の投稿は変わらない。Slackは投稿時の名前を記録する |
| `invalid_auth` | トークンが違う。`xoxp-` ではなく `xoxb-` |
| 朝に届かない | その時刻にClaude Codeが閉じていた。次に開いた時に届く |
| 「N完了」が効かない | 前日の `record` が走っていない。`mietask sync thread` で確認 |
| どこが悪いか分からない | Claude に「ミエタスクを診断して」と言う（`mietask doctor`） |
| 「管理台帳で停止されています」 | 管理者が台帳で停止にしている。管理者に確認する |

## チャンネルは一人に1つ

チャンネル名は**ワークスペース全体で一意**なので、全員が同じ名前にはできない。
既定は `ミエタスク-<名字>`（例 `ミエタスク-yamada`）。同じ名字がすでにあれば `ミエタスク-shino-yamada` のように名前も付ける。

同じ名前がすでにある場合、**セットアップは黙ってそれを使わずに止まる。**
他人のチャンネルに自分のタスクを流さないため。別の名前にするか、
自分のものだと確認できたIDを渡す。

できたチャンネルには**本人とBotしかいない。** 他の人は入れないこと。

## 一覧が出るのは自分のチャンネルだけ

タスクには顧客名や社内の依頼内容、DM・非公開チャンネル・メールから拾った内容がそのまま入る。
だから一覧が出るのは自分のチャンネルだけにしてある。管理者には、**案件ごとの状態と、いま何をしているかの一言だけ**を届ける。

| | 見られる人 | 中身 |
|---|---|---|
| 自分のチャンネル | 本人だけ（とBot） | 一覧の全部。返信案も入る。最後のスレッドに「管理者に届く内容」 |
| 管理者のページ（ダッシュボード） | 本人と、そのチームの管理者（部門長は下のチームも）・役員 | 人ごとの持っている案件の並び（関わり方・いまの状態の一言・相手待ち・しばらく動きなし）と、それを確かめる補助の案件ごとの並び（誰がどの役割で関わっているか・期間の進み具合）。MTD の案件と、ミエタスクの案件ごとの要約を合わせたもの |
| 管理台帳の「案件の要約」 | 台帳を編集できる人 | 上の要約そのもの |
| 管理台帳の「日々の状態」 | システム管理者（と、台帳を編集できる人） | 動作の点検用。毎朝の件数（超過・今日・今週）と、届いた時刻だけ |

- **管理者のページに、各自の一覧は出ない。** 窓口（管理台帳の Apps Script）は、本人の投稿先以外への投稿を断る。方針ではなく仕組みで止めている
- 管理者のページは1つの URL を全員に配り、**見る人によって中身が変わる。** 社内の Google アカウントで開き、見える範囲は台帳の「チーム」シートの「管理者」と「メンバー」シートの「ロール」で決まる（ページの側では決めない）
  - メンバー（ロールが空でもよい）：「自分」（自分のチャンネルの「管理者に届く内容」と同じ）と、自分の関わる「案件」
  - 管理者（「チーム」の管理者欄にいる人）：「メンバー」のタブで、そのチームと、その下のチームの人（リーダーはチーム、PM長や部門長はその上のチームの管理者にする）。気にすべきものがある人から並ぶ
  - 役員：全員
  - システム管理者：「管理」のタブで、全員の動作状況（動いているか・最後に動いた時刻・版・要約が届いた日）と台帳の書き方の誤り。案件の中身は見えない
  - ロールは「役員, システム管理者」のように重ねられる
  - 案件のタブでは、見える範囲の外の人は名前を出さず「ほかに N人」とだけ出す
- 管理者に届く一覧は、本人の手元の「持ち案件の台帳」（`~/.mietask/data/projects.json`）そのもの。最初の1回で Slack・カレンダー・MTD・タスクから持っている案件を洗い出し、毎朝は動きのあった案件だけを更新する。3週間動きが無ければ「しばらく動きなし」、6週間で外れる。本人が「〇〇は終わった」と言えばその場で外れる（`mietask projects`）。社内の案件など、MTD に出てこない仕事もここから見える。タスクの題名・人の名前・メールや DM の文面・人事や健康などの内々の話は入れない。窓口もリンク・メンション・メールアドレスの入ったものは受け取らない
- 案件の名前は、本人の MTD の案件名と、同じチームの人が最近使った案件名を手がかりに寄せる（`mietask share hints`。各自の Claude に渡るのは案件名だけ）。それでも別の名前で届いたものは、システム管理者が管理のタブの「案件の別名」で束ねる（台帳の「案件の別名」シート。変更の記録に残る）
- 出したくない案件は、Claude に「〇〇は管理者に出さないで」と言えば翌朝から出ない
- 毎朝の件数（超過・今日・今週）のほかは、送られてきても窓口が受け取らない。毎朝の件数はチームの管理者には見せない（除外の仕方が人ごとに違い、人どうしで比べられないため）。案件ごとの残りと超過の件数は、その案件の進み具合として管理者のページに出る
- チームの管理者は1on1の前に「〇〇さんの状況」と聞けば、同じ材料（MTD と案件ごとの要約）から状況をまとめてくれる（`team-sheet`）

返信案は作るが、**送信はしない。** 送るかどうかは必ず自分で決める。

### 管理者が気をつけること

- 誰が誰の分を見られるかは、台帳の「チーム」シートの「管理者」と、「メンバー」シートの「チーム」「ロール」で決まる。「チーム」シートの「親チーム」で部門 → チームの木を作り、各チームの「管理者」にそのチームを見る人を入れる（1つのチームに複数人でもよい。管理者がそのチームに所属している必要はない）。管理者が替わったら、そのチームの管理者を差し替えるだけでよい（Slack のチャンネルは使わない）
- 以前は管理者をロールで付けていた。その台帳は、メニューの「シートを整える」を1回押すと、管理者のロールの人がその人の「チーム」の管理者に移る（移すまでは以前どおりロールで決まる）
- 台帳の「メンバー」の「メール」は、社内の Google アカウントと同じにする（ページはこのメールで本人を見分ける）。ミエタスクを使わない管理者・役員も、ページを見るには「メンバー」に行が要る（鍵は発行しなくてよい）
- システム管理者は、ロールに「システム管理者」を入れる。不具合のときに確かめられるよう、全員の動作状況と点検用の件数を見られる。以前の「設定」の `system_admins` は、メニューの「シートを整える」でロールに移せる（ロールが空の人にだけ入る）
- システム管理者は、管理のタブでメンバーを足し、鍵を DM で送り（鍵は画面に出ない）、名前・チーム・ロール・状態・メール・Notion ユーザーと、チームの追加・表示名・親チーム・管理者を変えられる。チームの管理者に選んだ人と、役員のロールを付けた人には、ページの URL と見方が本人に DM で届く。変えたものは台帳の「変更の記録」シートに残る（シートを直に直してもよいが、その分は記録に残らない）。ページを開いたあとにシートが直されていたら上書きせずに断る。システム管理者が1人もいなくなる変更はできない
- 管理者のページは、管理台帳とは別の Apps Script（`admin/dashboard`）で出す。Notion でインテグレーション（読み取りだけ）を作って MTD のプロジェクトDB・タスクDBに接続し、台帳のメニューで「Notionの鍵を設定する」→「ダッシュボードの合言葉を作る」。出た2つの値をページの Apps Script のスクリプト プロパティに入れ、「組織内の全員」に公開する
- 導入してもらう前に、**一覧の中身はほかの誰にも届かない**こと、管理者には**案件ごとの状態と一言だけ**が届くこと、動作の点検のためにシステム管理者が件数を見ることがあることを本人に伝えておく（セットアップの最後にも本人に伝わる）
